# 工程结构与关键约束

作者：dxy。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `adapters/douyin` | 分享链接、接口、RENDER_DATA、React Flight 和目标作品解析，浏览器生命周期 |
| `adapters/transfer.py` | 无水印地址筛选、下载校验、临时文件及原子落盘 |
| `adapters/media.py` | 图片方向及尺寸标准化，调用 FFmpeg 合成 H.264/AAC MP4 |
| `application/service.py` | 素材获取、下载、缓存校验、合成和元数据流程编排 |
| `presentation/gui.py` | 窗口、主线程事件队列和用户交互，不负责解析网站数据 |
| `presentation/cli.py` | 参数和启动方式选择，调用与 GUI 相同的下载服务 |
| `infrastructure` | 浏览器安装、FFmpeg 下载与校验、子进程取消、日志及打包环境 |
| `domain/models.py` | 模块之间的内容、选项、结果、回调类型和异常契约 |

## 核心行为

- 按作品 ID 匹配数据，防止把相关推荐误当成目标作品。
- 先显示 GUI，再进行网络操作；后台线程通过队列报告状态，禁止直接更新 Tk。
- 完成、失败和警告状态保持可见，不定时销毁窗口；取消后等待请求结束并回收浏览器和 FFmpeg。
- 下载和合成只在成功校验后替换正式文件。失败不会留下伪装成完整作品的 MP4。
- 已下载文件按元数据里的大小和 SHA-256 校验后复用，不以“大于某个大小”推断成功。
- 无 Content-Length 的响应也更新下载字节数和速度。
- 图文原图、动态视频和配乐先保存。有配乐时各项均分音频时长，动态短片循环播放；无配乐时动态短片保留原始时长，静态图片按 `--slide-seconds` 设置。
- Live Photo 原始视频另存为 `live_*.mp4`，合成时使用动态视频作为画面源，不能用静态封面代替。
- 动态流获取失败直接报错；缺少配乐时记录警告。已完成素材保留以便重试。
- 合成缓存同时核验静态图、动态流及音频哈希，旧静态合成结果不能复用为动态导出。
- Cookie 与签名 URL 只用于本次请求，不写入元数据或发布包，日志中的 URL 会脱敏。
- Windows exe 首次合成时按 SHA-256 校验并下载独立 FFmpeg，不在发布包里重分发该 GPL 二进制。
- Chromium 首次使用时下载当前 Playwright 对应版本，macOS 使用系统标准缓存目录。
- 图片的 `download_url_list` 实测可能带平台水印，优先选择 `url_list`，下载前及重定向后再次拒绝已知水印地址。
- 缓存带素材策略版本，旧策略下载的图片和衍生视频必须重新获取与合成。

## 本地与发布边界

`AGENTS.md`、虚拟环境、历史备份、下载素材、日志和构建中间文件均为本地文件。
源码归档使用路径白名单生成；发布压缩包只包含可执行文件、README、许可证和变更记录。
发布包不会包含 Chromium、浏览器 Cookie 或个人下载素材。

CLI 使用安装后的 `douyin-downloader` 或 `python -m douyin_downloader`。
`scripts/desktop_entry.py` 是独立程序的构建入口；历史本地启动器和验收记录不提交到 Git。
